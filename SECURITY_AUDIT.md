## Executive Summary

pgforge's overall security posture is moderate: the engine demonstrates mature anti-enumeration intent (constant-time decoy hashing, always-200 reset/resend flows) and a layered tenant model (app-level scope plus Postgres RLS), but several controls fail open or are silently bypassed on alternate code paths. The single most urgent issue lives in the bundled `portico` WebSocket transport: an unbounded 64-bit frame length is read straight off the wire and used in a size calculation that integer-overflows the completeness guard, yielding an unauthenticated remote out-of-bounds heap write (crash/RCE) from any peer that completes the handshake. The authorization layer has two systemic weaknesses worth equal attention: the policy engine is **fail-open by default** on tables not explicitly listed, and the OAuth/OIDC login path entirely skips MFA enforcement while auto-linking federated identities on a single provider-asserted `email_verified` boolean, enabling MFA bypass and cross-provider account takeover.

Top risks, in priority order:
1. **Remote OOB heap write via WebSocket frame length overflow** (unauthenticated, crash/RCE).
2. **Deny-by-default authorization gap** — un-listed tables are fully accessible out of the box.
3. **OAuth path bypasses MFA + cross-provider account takeover** via email-only linking.
4. **Memory-safety bugs in the transport library** (slot double-free, double-close/fd-reuse race).

Recurring themes (see Cross-Cutting at the end): silent fail-open on alternate paths;
OAuth/RPC/realtime each skip a control the password/data-op path enforces; the transport
lacks enforced upper bounds and idle reaping; an information-disclosure cluster.

## Cross-Cutting Recommendations

- **Fail closed by default.** H-1, H-9, M-3, L-4 are all silent fail-open on alternate paths. Absence of an explicit allow must be a deny; reject ambiguous configs at load with a hard error.
- **One consistent identity/MFA/tenant pipeline.** OAuth (H-2, H-3, M-4), RPC (H-4, M-3), realtime (M-5, L-4) each skip a control the password/data-op path enforces. Route every path through the same MFA check, `make_scope` gating, and RLS envelope.
- **Bound everything from the wire.** C-1, H-6, H-7, H-8, M-9: wire `max_frame_size`/`ping_interval`/`pong_timeout` into the parser/event loop; add a reassembly cap.
- **Stop leaking existence and internals.** H-5, M-7, L-1, L-2, L-3: standardize generic client-facing errors (mirror the already-correct reset/resend endpoints) and authenticate `/metrics`.
